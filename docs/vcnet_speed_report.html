VCNet 速度優化報告

本報告整理 VCNet 在訓練與推論兩方面的加速：各用了哪些技術、在 H100 上量到多少、哪些試過但不採用。 與 bViT 共用的推論技術只簡述，細節見 README 的「實際延遲與吞吐量」到「H100 三個種子」各節。

1摘要

  • 4.6×
    adapt_blt（8 步）的訓練速度：每秒 1,484 → 6,858 張。3 個種子從約 300 分鐘降到約 65 分鐘（依序跑）。 bench_train.py，batch 256，閒置 H100
  • 2.9×
    原始 VCNet（2 步）的訓練速度：每秒 8,382 → 24,387 張，每次訓練約 6 分鐘。 主要來自 CUDA graph 與 GPU 上的資料增強
  • ±0.35
    快速管線重現第 1–2 輪的準確率：blt 每步差 +0.1～+0.35 點，orig 差 +0.9 點，都在種子差異之內。 3 個種子；校準（溫度縮放後的 ECE、NLL）相同
  • 8.4×
    batch 256 的推論：blt 固定 2 步從 eager 每秒 12,572 張到「編譯 + 一張 CUDA graph」105,289 張， 是原始 VCNet（115,122）的 91%，準確率高 2.8 點。graph-compiled-bs256 模式
  • 1.05×
    自適應的槽位池在 λ=0.1 對同準確率的固定 3 步快 5%，但只有固定步數前緣的 0.89 倍；即使沒有任何額外開銷，上限也只有約 1.10 倍。 batch 256，3 個種子
  • batch 1
    自適應在 batch 1 有效：blt + 停止策略 1.78–1.83 ms、67.77%，原始 VCNet 2 步 1.91 ms、64.56%； 對 blt 自己的固定 3 步約快 1.4 倍。CUDA graph，閒置 GPU

結論：新實驗預設用快速訓練管線（GPU 增強 + 編譯 + CUDA graph + fused AdamW，batch 256，依序執行）； CIFAR 上的 batch 推論用「固定步數 + 編譯 + CUDA graph」，自適應步數留給 batch 1 與之後較大的影像。

2時間花在哪裡

第 1–2 輪的訓練幾乎沒用到 H100 的算力。adapt 每個 epoch 16.6 秒（約每秒 2,700 張），換算約 8 TFLOPs，不到 bf16 峰值的 1%。 VCNet 每步只有約 0.12 GFLOPs，卻由幾十個小模組組成；8 步的訓練一次 iteration 有約 360 個前向卷積與 360 個反向卷積，每個 20–50 µs。 時間主要花在三個地方：

瓶頸現象對策
CPU 發送 kernel每次 iteration 數千個小 kernel，GPU 在等 CPU；orig 只編譯不錄 graph 反而慢（0.92×）CUDA graph：每步只發送一次
CPU 資料增強PIL + RandAugment 用 7 個 worker 上限約每秒 11,500 張；orig 錄成 graph 後卡在這裡（11,895）資料放 GPU，在 GPU 上逐張增強
主機同步GPU 增強每批把幾個常數從 CPU 複製到 GPU，每次複製都會阻塞，CPU 要等上一個訓練步做完才能排下一批常數只建一次並留在 GPU；下一批在副串流上增強

推論也一樣：batch 256 時 eager 的 blt 2 步每秒只有 12,572 張，編譯但不錄 graph 是 40,590，兩者都受發送開銷限制。 自適應的壓縮式 runner 每步要同步一次並把已停的影像移出，後段 batch 越來越小，吞吐量只有固定步數的 27–42%。

3訓練加速：技術

四項改動都是開關，預設仍是第 1–3 輪的做法，所以舊實驗的結果可以照原樣重現。新實驗的設定集中在 fsv/experiments.py 的 _FAST： --gpu-aug --compile-mode reduce-overhead --opt-impl fused。這些都與模型無關，bViT 也能直接使用；它們是為 VCNet 寫的，bViT 沒有對應的舊做法。

3.1　GPU 上的資料增強（fsv/gpu_aug.py）

  • 訓練集以 uint8 整份放在 GPU 上；GPULoader 每個 epoch 在 GPU 上產生排列，取一批後逐張增強，取代 DataLoader。
  • 同一套增強：RandomCrop(32, padding 4) → 水平翻轉 → RandAugment(2, 9) → Normalize → RandomErasing。 每張圖、每一輪各自抽操作；同一輪的 5 種幾何操作（剪切、平移、旋轉）合成一次 grid_sample。
  • 正確性：14 種 RandAugment 操作逐一與 torchvision 的 uint8 實作比對。幾何、亮度、對比、色調分離、曝光、自動對比、直方圖等化完全相同； Color 與 Sharpness 因捨入最多差 1 個灰階；RandomErasing 的觸發比例與平均面積相符。亂數序列不同，所以另外用準確率驗證（第 4.2 節）。
  • 沒有主機同步（0.15.1）：所有常數（平均、標準差、旋轉中心、銳化核、索引）在第一次使用時建在 GPU 上並快取。 第一版每批都從 Python 值建這些 tensor，每次都是阻塞的 CPU → GPU 複製，CPU 因此等 GPU 做完上一個訓練步，增強與訓練完全沒有重疊。
  • 副串流預取：第 k 步訓練在主串流上執行時，第 k+1 批在副 CUDA 串流上增強；用 wait_stream 與 record_stream 保證順序與記憶體生命週期。

3.2　編譯 + CUDA graph 的訓練步（fsv/train_step.py）

  • torch.compile 編譯「所有步的前向 + Stage A 損失」這一整個函式，反向由 AOTAutograd 一起編譯；Inductor 把 GroupNorm、CBAM、通道注意力等小運算融合。
  • reduce-overhead 再把前向與反向錄成 CUDA graph（cudagraph trees）：每步 CPU 只重播 graph。每步開頭呼叫 cudagraph_mark_step_begin()， 回傳的損失分量先 clone，因為下一次重播會覆寫 graph 的輸出。形狀必須固定，兩種 loader 都 drop_last。
  • Mixup / CutMix 留在編譯函式之外：它們每步抽一個新的 Python 浮點數 λ，放進去每步都會重新編譯。
  • 編譯一次約 25–145 秒（每次訓練只付一次）。

3.3　fused AdamW

--opt-impl fused：AdamW 用單一 kernel 的 CUDA 實作。單獨使用時影響很小（orig 1.04×），但在 CUDA graph 之後，每步剩下的發送次數主要來自最佳化器，這時就有用。

3.4　訓練時的雙線性上採樣改成矩陣乘法（0.15.2）

剖析 blt 的訓練步（編譯、不錄 graph，每次 iteration 約 40 ms 的 GPU 時間）發現，最貴的單一 kernel 是 AIT → V1 雙線性上採樣（4×4 → 32×32）的反向： Inductor 把 upsample_bilinear2d 的反向變成帶 atomic add 的 index_put，每次 526 µs、每次 iteration 7 次，約佔 9%。 訓練時改成 U_h @ x @ U_wᵀ（bilinear_matrix 算出與 align_corners=False 相同的權重），反向也是矩陣乘法。 推論時仍用 F.interpolate，所以評估結果、延遲與量到的 FLOPs 都不變。實測 blt 快 4%（6,577 → 6,858 張/秒），batch 1024 快 9%。

3.5　訓練路徑不打包狀態

有 lat / blt 時，每一步的狀態是 7 個腦區的特徵圖。推論介面把它們打包成一個 [B, N] tensor，讓 runner 能統一索引； 訓練用的 forward() 改成步與步之間直接傳各腦區的 dict，不再每步打包、拆包。輸出與逐步介面完全相同（測試確認）。

5.2　VCNet 特有的部分（0.16.0–0.16.1）

  • 每列各自的步數：forward_step(state, t, x0) 的 t 可以是每列一個步數的 long tensor。 預測誤差回饋、側向、由上而下各項對所有列都算，只在 t > 0 的列保留（torch.where），所以第 0 步的列得到的正好是純由下而上的一次掃描，舊狀態只被忽略、不會被乘到； 讀出依每列步數取步數嵌入。與逐批計算逐位元相同（測試）。bViT 的權重跨步共用，本來就能這樣做；VCNet 的第 0 步與之後的步計算不同，需要遮罩。
  • 兩份緩衝區：bViT 的狀態就是嵌入，VCNet 的狀態（AIT，或 lat / blt 時打包的 7 個腦區）與嵌入（V1）不同，所以槽位池分成 x0 與狀態兩份。 VCNet 平均 1.4–2.4 步就停，每個 tick 空出的槽位比 bViT 多，補位上限預設為全部 S 個。
  • 預先計算 V1：V1 在全解析度，每張圖只算一次，但佔每張圖約 1/4 的時間。補位時只做 gather，V1 在跑 tick 之前以 S 張一批先算好， 不必每個 tick 對所有補位候選算 V1（大多數候選不會被補上）。0.16.1 把這一步也編譯並錄成 CUDA graph：0.16.0 在編譯模式下它仍是 eager， 而 eager 的 blt kernel 即使在 graph 內也比編譯過的慢約 2 倍。這一項讓槽位池快了 10–16%。
  • 公平的對照組 FixedDepthGraph：固定 t 步時，batch 256 的整個前向（V1 + 第 0..t 步 + 讀出）錄成一張 CUDA graph，可先編譯（每個步數一個編譯圖）。 第 10 輪的 bViT 比較用的是 eager 固定步數，高估了槽位池；這是最強的固定步數做法。
  • 前緣比較：除了「準確率不低於自適應的最便宜固定步數」，再加上「把每張圖隨機分到相鄰兩個固定步數、使平均準確率相同」的吞吐量。 自適應落在兩個固定步數之間時，前者會讓它看起來比較好；後者才是停止策略要贏過的線。

6.4　每張圖的時間組成（λ=0.1）

上限：即使 tick 沒有額外開銷，λ=0.1 也只有約每秒 98,000 張、前緣的約 1.10 倍。原因有三：平均只有 1.74 步，自適應最多省下 2 步與 3 步之間的一部分； V1 每張圖都要算（約 1/4 的時間），與步數無關；在槽位裡，第 0 步的列也付一次帶回饋的步數成本（約 3.9 µs），固定步數的第 0 步只是純掃描（約 2.7 µs）。

7結論與未完成項目

  • 訓練：新實驗一律用 _FAST、batch 256、依序執行。在同一張閒置 GPU 上，orig 快 2.9 倍、adapt_blt 快 4.6 倍，準確率在種子差異內。
  • batch 推論：CIFAR-100 上用固定步數 + 編譯 + CUDA graph（FixedDepthGraph(compile=True)）。blt 2 步每秒 105,000 張，比原始 VCNet 高 2.8 點，速度是它的 91%。
  • 自適應：batch 1 有效；batch 256 的槽位池到前緣的 0.82–0.89 倍，理論上限約 1.10 倍。影像更大、每張圖的步數更多時（階段 4）空間較大，屆時再量。
  • 未做：
    • 每個腦區各用一份狀態緩衝區（不打包）、調整補位上限：預估最多再快 5–10%，擱置到階段 4。
    • MPS 並行多個訓練行程（可選）。
    • 階段 1 的縮窄 VCNet（vcnet_r56p / r56f4）訓練反而比全寬慢，可能是通道數不是 8 / 16 的倍數，bf16 卷積用不到快的 kernel；尚未驗證，之後的新寬度取 16 的倍數。
