VCNet 自適應步數報告

本報告說明 VCNet（仿視覺皮層 CNN）的實作、我們把它改成「步數可變」模型的方式，以及到第 2 輪為止的實驗結果。 研究問題是：原始 VCNet 與 VCNet + 自適應步數 在準確率、計算量、延遲、校準度上差多少。

1摘要

  • 64.55%原始 VCNet
    0.275 GFLOPs

    依論文重新實作的原始 VCNet（1.02M 參數，由下而上一次 + 預測編碼修正一次），CIFAR-100 測試準確率，3 個種子平均。

  • 65.30%adapt_carry 固定 2 步

    第 1 輪：把預測編碼迴圈展開成最多 8 步、每步讀出。迴圈修正一次後就飽和，第 3–8 步沒有增益；停止策略贏不了固定步數。

  • 67.27%adapt_blt 固定 2 步
    0.284 GFLOPs

    第 2 輪：讓每個腦區保留跨步狀態，並加入 BLT 式由上而下連線。同樣計算量下比原始高 2.7 點，而且一直進步到第 4 步（68.68%）。

  • 67.77%adapt_blt + 停止策略
    0.252 GFLOPs

    加上停止策略後，以原始模型 91% 的計算量高 3.2 點。這是停止策略第一次在同一個模型內勝過固定步數（2 步的計算量下 68.18% vs 67.27%）。

  • 1.78 msbatch 1 延遲
    blt + 停止策略

    閒置 GPU 重量：batch 1（CUDA graph）下，blt + 停止策略比原始 VCNet 跑 2 步（1.91 ms）略快，準確率高 3.2 點。 batch 256 則相反：停止策略讓吞吐量降到固定步數的 27–42%，原始 VCNet 與 blt 固定 2 步的吞吐量相近（41,499 vs 39,804 張/秒）。

  • 待第 3 輪架構 vs 自適應

    相對原始模型的增益大部分來自架構（跨步狀態），不是自適應。第 3 輪用同樣架構、照原始方式訓練，把兩者分開。

2背景

2.1 專案目標

fast-slow-vision 研究「校準過的快慢視覺」：一個權重共用的遞迴模型，每算一步就輸出一次校準過的類別機率， 再由小型停止策略依目前狀態與計算價格 λ 決定停或繼續。簡單的圖早停、難的圖多想，單一模型涵蓋整條準確率–計算量曲線。 先前的骨幹是 bViT（單區塊遞迴 ViT）；本分支改用 VCNet。

2.2 VCNet 論文

Hill, Zhang & Prasetio（2025），arXiv 2508.02995，NeurIPS 2025 workshop。 模仿靈長類視覺皮層的巨觀結構：腹側流（V1→V2→V4→PIT→CIT→AIT）、背側流（V1→V2→MT→MST）、 AIT 對 V1 的預測編碼回饋。論文在 Spots-10（32×32 灰階）上報告 92.08%、光場資料上 74.42%。

論文沒有程式碼，也沒有通道寬度、步長、正規化方式、分類頭與回饋迴路的接法；實驗只有單次執行，沒有消融，也沒有 CIFAR / ImageNet 結果。 因此本報告的「原始 VCNet」是依論文描述加上明確假設的重新實作（見 3.1）。

2.3 研究問題

  1. 原始 VCNet 與 VCNet + 自適應步數，在相同計算量下的準確率差多少？在相同準確率下省多少計算與延遲？
  2. VCNet 的哪個部分可以當作「可變的步數」？多跑幾步是否真的有用？
  3. 學習式停止策略能否勝過固定步數與信心門檻？

3方法

3.1 原始 VCNet 的實作

論文有寫的部分照做：V1 為三條平行的 depthwise-separable 卷積（3×3、5×5、7×7）後串接，接側向交互（卷積 + channel-wise self-attention + 殘差）、 CBAM、神經調制（逐通道可學習縮放）；MT、MST 的遞迴區塊為 zi+1 = f(zi) + z0，迭代 3 次； 預測誤差 ε = ReLU(V1bottom-up − AITtop-down)。論文沒寫的部分以下表的假設補上。

項目本實作的選擇理由
通道寬度V1 48、V2 64 / 32（背側）、V4 80、PIT 80、CIT 128、AIT 160、MT 64、MST 80參數量 1.02M（3.9 MB），接近論文的 3.52 MB
降採樣V2、V4/MT、CIT/MST 各以 stride 2 降一半：32 → 16 → 8 → 4論文未提
正規化、活化GroupNorm（最多 8 組）+ ReLU專案規定不得用每步統計的 BatchNorm

分類頭AIT 全域平均池化 → LayerNorm → 加步數嵌入 → Linear與 bViT 共用同一種讀出頭

3.2 把迴圈變成可變的步數

論文唯一可以反覆執行的機制是 AIT → V1 的預測編碼回饋，所以一步 = 一次預測編碼迴圈：第 0 步只做由下而上的計算； 之後每一步，AIT 預測 V1、算出誤差 ε、修正 V1 的輸入，再跑一遍 V2…AIT。每一步之後都用共用讀出頭輸出一次機率 pt。 模型實作與 bViT 相同的介面（embed / forward_step / readout），所以訓練、評估、停止策略與延遲量測的程式都不用改。

z0 = V1　　zt = V1 + W·ReLU(V1 − 上採樣(P(AITt−1)))　　AITt = Sweep(zt)　　pt = softmax(head(LN(pool(AITt)) + et) / Tt)

3.3 跨步狀態與由上而下連線（論文以外的延伸）

第 1 輪發現迴圈修正一次就飽和。推測原因是每一步唯一的新資訊只有 V1 輸入的小修正，V2…AIT 每步從零重算、不記得上一步。 第 2 輪加入兩個仿皮層機制，兩者的新連線都初始為 0，所以新模型訓練剛開始時與原本的迴圈完全相同。

開關做法來源
--lateral每區 A ∈ {V2, MT, V4, PIT, CIT, MST, AIT}：At = F(這一步的輸入) + RA(At−1)，R 為 1×1 卷積CORnet-RT 的區內遞迴（Kubilius et al., 2019）
--topdownAt += TA(上採樣(Bt−1))，B 為同一流的上一層：V2←V4、V4←PIT、PIT←CIT、CIT←AIT、MT←MST、MST←AITBLT 網路（Spoerer et al., 2017、2020）
--ait-carry只有 AIT：AITt += g·AITt−1，g 為逐通道係數第 1 輪的簡化版

七個腦區的狀態打包成一個張量，所以線上停止、batch compaction、CUDA graph 的程式不用改。

3.4 變體一覽

名稱怎麼讀：adapt_ 開頭的都是「自適應步數」版本：把原始 VCNet 的預測編碼迴圈展開成最多 8 步、每一步都讀出一次答案， 推論時由停止策略決定每張圖跑幾步。後綴說明各區如何把上一步的結果帶到下一步：

adapt
只有 AIT→V1 的預測誤差回饋；V2…AIT 每步從零重算。
adapt_carry
carry = 帶著。在 adapt 之外，最高層 AIT 加上自己上一步的輸出：AITt += g·AITt−1。
adapt_lat
lat = lateral（側向 / 區內遞迴）。七個腦區都加上自己上一步的輸出，仿 CORnet-RT。
adapt_blt
blt = Bottom-up、Lateral、Top-down。adapt_lat 再加上「上一層在上一步的輸出」往下傳，仿 BLT 網路。

「固定 N 步」：推論時不用停止策略，每張圖都跑 N 步（第 0 步到第 N−1 步），讀取第 N 步的答案。 自適應模型訓練時每一步都有讀出，所以可以在任何一步截斷；「固定 N 步」就是把它當成一般的 N 步模型用，作為停止策略的對照組。 與之相對，「停止策略」是每張圖各自決定跑幾步，表中列的是平均步數。

3.5 訓練、校準與停止策略

  • Stage A 損失（自適應變體）：L = Σt wt[CE(pt, y) + β·Brier(pt, y)] + γ·LGatekeeper + δ·Σt<T KL(sg(pT) ‖ pt)， β = 1、γ = 0.5、δ = 0.5，wt ∝ (t+1)2。原始模型只用最後一步的 CE。
  • 每步溫度縮放：骨幹凍結，在 5,000 張 held-out 影像上對每一步擬合一個溫度 Tt。
  • 停止策略：2 層 MLP（hidden 64），輸入為機率統計（top-5、熵、top-1/top-2 差、與上一步的變化、步數）與 log λ； 以 held-out 上快取的每步輸出離線訓練。主要使用的版本是 S0-reward_acc（獎勵 = 是否答對 − λ·步數/Tmax）。 推論時調 λ 即得到不同的速度–準確率取捨點。停止策略本身的成本小於一步的 0.01%。
  • 基準：固定步數、max-prob 門檻、熵門檻，以及 oracle（每張圖在最早答對的步停，作為上限）。

5.5 延遲與吞吐量

batch 1 是一次處理一張圖，看延遲（毫秒）；batch 256 是一次送 256 張，看吞吐量（張/秒）。執行模式有三種： eager（一般 PyTorch）、compiled（torch.compile）、CUDA graph（只用於 batch 1，去除 kernel 發送開銷，最接近計算量本身）。

  • 閒置 GPU 重量（主要數據）：orig、adapt_carry、adapt_blt 各 3 個種子，同一個行程、GPU 上沒有其他程式。 執行的程式是分支 claude/admiring-franklin-6zlsn0：含本分支的 VCNet，另多了「-triton」模式，把停止策略的特徵計算與 MLP 融合成一個 Triton kernel。 原始結果存於 results/vcnet_bench_idle_h100/raw.txt。
  • 評估時的固定步數量測：每個模型訓練完立刻單獨量（eager，不含停止策略），涵蓋全部模型。
  • 舊 benchmark：adapt（第 1 輪）與 adapt_lat（第 2 輪，量測時有其他程式）沒有重量。

原始 vs 自適應（閒置 GPU）

準確率、平均步數與吞吐量為 3 個種子的平均；batch 1 CUDA graph 為 3 個種子的中位數（滑鼠移到格子上可看各種子）。 「+Triton」為停止策略融合成單一 Triton kernel 的版本，固定步數不受影響。

  • batch 1：自適應有效。adapt_blt + 停止策略在 λ=0.1 為 1.78–1.83 ms、67.77%；原始 VCNet 跑 2 步為 1.91 ms、64.56%。 延遲少 4–7%，準確率高 3.2 點。λ=0.3 為 1.49–1.58 ms、66.74%（延遲少 17–22%，高 2.2 點）。 和 blt 自己的固定步數比，λ=0.03 以 1.99–2.13 ms 達到 68.20%，固定 3 步要 2.92 ms 才有 68.29%，快約 1.4 倍。
  • batch 256：自適應無效，固定步數較好。compiled 模式下，adapt_blt 固定 2 步為 39,804 張/秒、67.28%，是原始 VCNet（41,499 張/秒、64.60%）的 96%，準確率高 2.7 點。 但加上停止策略後只剩 10,644–16,774 張/秒（固定 2 步的 27–42%），準確率也沒有超過固定 3 步（27,081 張/秒、68.34%）。 原因是每一步都要找出並移除已停的影像，之後的 batch 越來越小，GPU 利用率下降。
  • eager 與 compiled：adapt_blt 在 eager 模式每步額外開銷很大（固定 2 步 11,610 張/秒，只有 compiled 的 29%）；原始 VCNet 在 eager 為 29,377 張/秒。 部署 blt 應使用 torch.compile。
  • Triton 融合 kernel：batch 1 CUDA graph 下，停止策略的延遲中位數再降 3–9%（blt λ=0.1：1.825 → 1.776 ms）。
  • 量測品質：固定步數的 CUDA graph 延遲三個種子幾乎相同（差 < 0.1 ms）；停止策略偶有單一種子偏慢（blt 種子 1 的 λ=0.1 為 3.10 ms，另兩個 1.81–1.83 ms），所以取中位數。 adapt_carry 種子 2 的停止策略在所有 λ 下都在第 0 步停。

固定步數（評估時量測，eager，全部模型）

吞吐量 = 256 ÷ 一個 batch 的時間。原始 VCNet 與 adapt 架構相同，2 步的吞吐量也相同（29,733 vs 29,595 張/秒）。 adapt_blt 在 batch 256 eager 每多一步約 16.8 ms，是 adapt（約 5.2 ms）的 3.2 倍，與閒置 GPU 重量的 eager 結果一致。

全部數據（依模型）

orig、adapt_carry、adapt_blt 為閒置 GPU 重量（3 個種子平均 ± 標準差；CUDA graph 為中位數）；adapt 為第 1 輪、adapt_lat 為第 2 輪（受干擾）。 標準差超過平均值 25%（或種子間差距超過中位數 25%）的格子以灰色虛線底線標出。 GFLOPs 為每張圖的計算量（含每步讀出）：固定 N 步為實測的累計值；停止策略列（標 ≈）是依平均步數估算： 0.161 + (平均步數 − 1) × 每步成本（adapt / carry / orig 0.113、lat 0.119、blt 0.122 GFLOPs），停止策略本身不到一步的 0.01%，忽略不計。 滑鼠移到估算值上可看式子與種子間的差異。

6討論與限制

6.1 為什麼第 1 輪會飽和、第 2 輪不會

原本的迴圈中，上一步留給下一步的只有 AIT 對 V1 的預測；中間各區每步從零重算。修正一次後，V1 的輸入幾乎不再改變，網路就停在同一個答案上。 讓每區保留自己的狀態後，每一步可以在上一步的中間結果上繼續加工；加上由上而下的連線（BLT），高層的資訊能逐層往下影響，後面的步數才有東西可以累積。 blt 進步到第 4 步、lat 在第 3 步左右飽和，與這個解釋一致，但尚未以消融直接驗證。

6.2 架構與自適應的貢獻混在一起

原始 VCNet 只在最後一步讀出、只用 CE；自適應變體同時改了架構（跨步狀態）、讀出方式（每步）、損失（Stage A）與推論（停止策略）。 從 5.3 看，停止策略本身在 blt 內約帶來 +0.3 到 +0.9 點（同計算量）；相對原始模型的 +2.7 以上大多來自架構。第 3 輪的對照組用來分開這兩者。

6.3 限制

  • 原始 VCNet 是依論文描述的重新實作，寬度、降採樣、回饋接法等都是我們的假設，結果不能直接當作論文模型的表現。
  • 只在 CIFAR-100（32×32）上實驗；論文的資料集（Spots-10、光場）與 ImageNet 都還沒做。
  • 3 個種子，表中為平均 ± 標準差，沒有逐種子的配對比較。
  • 自適應只在 batch 1 帶來延遲上的好處；batch 256 時停止策略讓吞吐量明顯下降。blt 的 eager 實作每步比 adapt 慢 3.2 倍，需用 torch.compile。adapt_lat 尚未在閒置 GPU 上重量。
  • 跨步狀態與 BLT 連線是論文以外的延伸，報告時須與原始 VCNet 區分。
