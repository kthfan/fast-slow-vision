摘要

我們自行實作 bViT 式單區塊遞迴 ViT（1.86M 參數，Tmax = 8），每一步都以共用讀出頭輸出類別機率，訓練後在 held-out 集上為每一步擬合溫度，再於快取的每步輸出上離線訓練停止策略。主要發現：

最佳共用權重模型的 top-162.14 ±0.31%平方步權重 + lr 5e-4；不共用的 8 區塊 ViT 為 62.63%（參數 7.7 倍）
達到全深度準確率所需計算量43%學習式停止策略；固定深度需 62%，max-prob 門檻需 83%
AUC 相對固定深度+0.4～+1.16 個骨幹全部勝出；相對門檻規則 +2～+3
同準確率下的實際速度比0.48～1.08×H100 上 FLOPs 的節省沒有轉成實際加速
  • 每步損失權重是共用模型的關鍵。均等權重讓共用模型在第 3–4 步就飽和；改為 wt ∝ (t+1)² 並把學習率降到 5e-4，最佳步從 59.34% 升到 62.14%，種子間差異也穩定下來。
  • 只用機率統計量（S0）的 λ 條件化 MLP 就夠了。它在所有骨幹上都勝過固定深度與 max-prob / 熵門檻，λ 掃描單調，成本不到單步遞迴的 0.03%。表徵特徵（S2、S3、S5）在 CIFAR 規模下沒有帶來好處。
  • 溫度縮放有效但不是瓶頸。模型普遍信心不足（Tt ≈ 0.70–0.90），縮放後 ECE 2–3%。
  • 實際時間沒有加速。每步計算量只有 0.24 GFLOPs，GPU→CPU 同步與 kernel 發送開銷和計算同一量級。CUDA graphs 讓 batch 1 快 3–4 倍，但自適應版本仍比同準確率的固定深度慢。

1研究目標與假說

目標是用單一個權重共用的遞迴模型涵蓋整條「準確率–計算量」曲線：簡單的圖早停、難的圖多想，並讓停止決策所依據的信心經過校準。規格見 TODO.md。三個假說在本階段的檢驗狀態如下。

假說內容本階段狀態
H1 效率校準且以 λ 為條件的停止策略，在準確率–計算量曲線上優於熵門檻、max-prob 門檻、ACT 與固定早退部分支持 FLOPs 上勝過門檻與固定深度；尚未與 ACT / RL 比較；實際延遲未改善
H2 穩健相同平均計算量下，把遞迴集中給難圖，能提升 ImageNet-C/-R/-A 的表現與校準未檢驗 尚未做分布偏移資料
H3 像人類停止步數與人類最短觀看時間（MVT）正相關，並與 IT 物體解答時間吻合未檢驗 需 ImageNet 規模與 MVT 資料

2方法

2.1 骨幹：bViT 式遞迴 ViT

bViT（Byra et al., 2026）沒有公開程式碼，依論文描述自行實作於 fsv/models/bvit.py：pre-norm Transformer 區塊、GELU、無 drop path。為 32×32 輸入與本專案需求所做的調整：patch size 4（64 個 patch + CLS）、Tmax = 8（論文 ImageNet 為 12）、一律 LayerNorm（論文為 RMSNorm）、每一步都讀出並計算損失（論文只在最後一步）。讀出頭為 head(LN(CLS_t) + step_emb(t))，所有步共用。設定 n_blocks = 8 時就是不共用權重、每層後有出口的 ViT 對照組。

2.2 Stage A：每步損失

L = Σ_t w_t · [ CE(p_t, y) + β · Brier(p_t, y) ]
    + γ · L_conf                              # Gatekeeper 式信心損失
    + δ · mean_(t<T) KL( sg(p_T) ‖ p_t )      # 最後一步自我蒸餾

β = 1、γ = 0.5、δ = 0.5。Lconf 依 Gatekeeper（Rabanser et al., 2025）的概念：答對的樣本維持交叉熵，答錯的樣本以 KL(U ‖ p) 推向均勻分布，兩者以 α = 0.5 混合（原論文的確切權重仍待確認，TODO-2）。步權重 wt 比較三種：均等、線性 ∝ t+1、平方 ∝ (t+1)²，皆正規化為總和 1。

2.3 Stage B：每步溫度縮放

骨幹凍結後，在 held-out 5,000 張上以 LBFGS 為每一步各擬合一個溫度 Tt（fsv/calibration.py）。之後所有停止規則與策略都使用縮放後的機率。

2.4 Stage C：停止策略

骨幹凍結後先快取每一步的 logits 與特徵，所有停止策略都在快取上離線訓練（一組實驗數分鐘）。策略為 2 層 MLP（hidden 64，GELU），每步輸出停止 logit，推論時在第一個 sigmoid > 0.5 的步停止。

代號輸入特徵說明
S0機率統計量top-5 機率、正規化熵、top-1 與 top-2 差距、top-1 是否改變、KL(pt ‖ pt−1)、top-1 連續不變的步數、步數 one-hot
S2S0 + CLS 特徵384 維原始特徵；MLP 第一層即學習式降維（相當於 S6）
S3S0 + 收斂訊號CLS 與 pooled 特徵：與前一步的 cos、相對變化量、與第 0 步的 cos
S5S0 + 隨機投影固定高斯矩陣 384 → 64
目標定義
reward_accλ 條件化，最小化 Eπ[ 1[第 t 步答錯] + λ(t+1)/T ]。每步輸出都已快取，期望值可精確計算，不需 RL 取樣
reward同上，以 Brier(pt, y) 取代 0/1 錯誤（對應 Stage C 的 RL 獎勵設計）
oracle_any監督式 BCE；標籤 t* = 最早一個之後都答對的步；每步都錯的樣本可在任何步停
oracle_full同上，但每步都錯的樣本標記為跑滿 Tmax

λ 在訓練時對每個樣本從 log-uniform [10−4, 10] 抽樣，以正規化後的 log λ 輸入 MLP；推論時掃描 λ 得到整條曲線。監督式策略則掃描停止門檻。輸出形式比較 O1（每步輸出停止機率）與 O3（在第 k 步一次預測每張圖的總步數，StepMLP，以精確期望獎勵訓練）。

2.5 評估指標

  • AUC：準確率–計算量曲線在 [第 0 步, 第 7 步] GFLOPs 區間的平均 top-1。以「全部在第 0 步停」為左端錨點，錨點與方法最便宜點之間以直線連接（隨機混合兩種設定即可達到）。
  • acc @ tk：在固定深度第 k 步的計算量下可達到的最佳準確率。
  • cost@full / cost@best：達到全深度 / 最佳固定深度準確率所需的平均計算量，以全深度計算量的百分比表示。
  • Oracle：知道標籤、在 t* 停止的上限參考，不是可實現的方法。
  • 校準：ECE（15 bins）、NLL、Brier、AURC（風險–覆蓋曲線下面積）。
  • 實際時間：同一行程內連續量測固定深度與自適應版本的 batch 256 吞吐量（含 batch compaction）與 batch 1 延遲（500 張，取中位數）。速度比 = 自適應吞吐量 ÷ 同準確率的固定深度吞吐量。

3實驗設定

3.1 資料

CIFAR-100（Hugging Face parquet 鏡像）。從 50,000 張訓練集固定切出 5,000 張 held-out，用於溫度縮放、停止策略訓練與模型選擇；其餘 45,000 張訓練骨幹。所有報告數字均為 10,000 張測試集。

3.2 訓練配方

項目設定
訓練長度200 epochs，batch 256
最佳化器AdamW（β = 0.9, 0.999），weight decay 0.05，梯度裁剪 1.0
學習率1e-3（第 5 輪起另測 5e-4），10 epochs 線性 warmup 後 cosine 降到 1e-5
資料增強RandomCrop 32（padding 4）、水平翻轉、RandAugment(2, 9)、Random Erasing 0.25

精度bf16 autocast（H100）；Kaggle 為 fp16 + GradScaler
損失β = 1、γ = 0.5、δ = 0.5、Gatekeeper α = 0.5；步權重依實驗而定

3.3 硬體與流程

第 1 次執行在 Kaggle（2×T4，DDP，fp16），之後全部在使用者的單張 H100 NVL 上執行，CPU 上限 8 核（DataLoader 7 個 worker）。一次 200 epochs 訓練約 10–22 分鐘。使用者以 scripts/run_experiment.py 執行登記在 fsv/experiments.py 的實驗，再以 scripts/summarize.py 輸出摘要貼回；原始摘要存於 results/round*_h100/。主要設定使用 3 個骨幹種子（0, 1, 2），停止策略另用 3 個策略種子；單一種子的結果在表中註明。

4.2 配方消融

第 1–6 輪的主要問題是「為什麼共用權重的模型在第 3–4 步就停止進步」。依序排除了訓練精度、增強強度、模型寬度、時間嵌入與輸入注入，最後找到的原因是每步損失權重：均等權重下前面的步佔了大部分梯度，共用區塊被拉去服務早期讀出。

4.3 校準

所有骨幹都有同樣的模式：縮放前 ECE 在第 1 步最高（偏重後段時第 1 步最差，13%），縮放後越後面的步 ECE 越高。8 區塊 ViT 的縮放前 ECE 隨步數下降到 3.6%，溫度也較接近 1（0.81–0.90）。是否需要比溫度縮放更強的校準（TODO-2：Brier、focal loss、label smoothing 的比較）目前看不出必要：停止策略的瓶頸不在校準（見第 5 節）。

5.1 準確率–計算量曲線

  • 學習式策略比門檻規則好約 2.3 AUC、比固定深度好約 0.4；同計算量下最多 +1.0 個百分點。
  • reward_acc（0/1 錯誤）一致優於以 Brier 為損失的 reward。oracle_full 把「最後一步也錯」的樣本送到最後一步，浪費計算量，明顯較差；oracle_any 與 reward_acc 相當。

提早決定會失去 O1 大部分的 FLOPs 優勢：O3 的 AUC 大致等於固定深度。它的價值只在於能否把剩下的優勢轉成實際時間，因為整個 batch 只需同步一次。

5.5 與 oracle 的差距

oracle any 在約 1.5 步（0.36–0.42 GFLOPs）就達到 62.4–66.4%，比任何方法的最佳點還高 2–4 個百分點。它的優勢主要來自讓「反正會錯」的樣本在第 0 步就停；這些樣本無法從機率統計量或表徵特徵中辨認出來，所以這個差距不能期待由更好的停止策略補上。

6實際延遲與吞吐量（TODO-4）

fsv/halting/online.py 的 AdaptiveRunner 逐步執行模型，增量計算 S0 特徵（與離線版逐位元相同，有測試），每一步把已停止的影像移出 batch，後段步數只處理剩下的影像。第 7–9 輪逐步減少額外開銷：

根本原因：只要每步同步一次，GPU 佇列就會清空，下一步約 55 個小 kernel 的 CPU 發送延遲（每個約 10 µs）全部暴露；這個模型在 batch 256 時每步只需約 0.5 ms，發送延遲與計算同一量級。第 9 輪再加入 O3（整個 batch 只同步一次、依預測步數排序後第 t 步只算前 nt 張）與 batch 1 的 CUDA graphs（CudaGraphBS1，決策與 eager 版 100% 一致）。

  • CUDA graphs 讓 batch 1 的所有方法快 3–4 倍（固定深度跑滿 8 步從 2.8 ms 降到 0.71 ms），但自適應仍比同準確率的固定深度慢。
  • O3 只同步一次，實際時間較好，但 FLOPs 優勢幾乎為零，所以最多打平。
  • 每步計算量越大，額外開銷佔比越小：bViT-S → bViT-B 時 batch 256 的 O1 從 0.48× 升到 0.89×，O3 首次略超過 1×。

結論：在 32×32 輸入、單步 < 1 GFLOPs 的設定下，H100 上無法把 FLOPs 節省轉成實際加速。實際延遲的主張需要每步計算量更大的設定（224×224 輸入、更寬的模型），或受計算量限制的硬體（CPU、邊緣裝置）。

7討論

7.1 這個架構在 CIFAR-100 上的天花板

三個觀察限制了自適應計算在這個任務上的收益：遞迴後段的幫助有限（約第 4–5 步飽和，第 2 步之後只再多 2–3 個百分點）；逐樣本的難度差異中等（多數樣本早就答對或怎麼算都錯）；每步計算量太小，實際時間由發送開銷主導。學習式策略穩定勝過基準，但絕對增益（約 +0.7 AUC）不大。

7.2 限制

  • 單一資料集、低解析度。所有結果都在 CIFAR-100；ImageNet 規模、分布偏移（H2）與人類 / 大腦比較（H3）都還沒做。
  • 部分消融只有一個種子（時間嵌入、輸入注入、無自我蒸餾、fp16、2 組 mixup、bViT-B）。它們的差異（±0.4）小於多種子設定的標準差上限，不足以下結論。
  • Kaggle 與 H100 的 2 個百分點差距未完全解釋；推測與 torch / torchvision 版本有關。
  • 延遲量測受共用 GPU 影響。部分 batch 1 CUDA-graph 項目的標準差很大（例如 1.354±1.393 ms，單一種子被干擾）；第 5 輪的延遲因其他工作而偏高，已不採用。
  • 比較對象尚不完整。ACT / PonderNet、RL 停止策略、兩模型串接（Hao et al. 2026）與 AdaPerceiver、A-ViT 等動態深度方法都還沒有重現。
  • Gatekeeper 損失的確切定義尚未對照原論文（TODO-2），教師蒸餾（η）未使用。

8結論與下一步

在 CIFAR-100 上，「校準 + λ 條件化停止策略」的離線結果符合 H1 的 FLOPs 部分：以只用機率統計量的 MLP，就能在所有骨幹上勝過固定深度與門檻規則，並以約 43–54% 的計算量達到全深度準確率；配方上，偏重後段的步權重讓 1.86M 參數的共用模型追上 14.28M 參數的不共用 ViT。但這個任務本身讓「多想幾步」的價值有限，實際延遲也無法改善。

使用者決定下一階段改找適合此架構的任務，並考慮加入仿皮層遞迴網路（TODO.md 第 4 節）。適合的任務應該讓多想幾步真的必要、難度可控且差異大，並能與人類反應時間 / 皮層動態對照。候選：

  1. 需要逐步傳播的視覺任務：路徑追蹤（Pathfinder、cABC）、迷宮、數數。難度可控、遞迴是必要的，可測試超出訓練步數的零樣本外推（AdRNN 2023）；人類曲線追蹤的反應時間隨路徑長度增加，猴子 V1 有對應的逐步傳播（Roelfsema）；hGRU、BLT 是自然的對照與骨幹。
  2. 遮擋 / 降質影像辨識：遮擋物體、低對比、模糊。遞迴處理與遮擋物體辨識有關（Kar 2019 的挑戰影像、IT 解答時間），直接對應 H2 與 H3。
  3. 由粗到細的分類：CIFAR-100 的 20 個超類別 / 100 個細類別，早期步回答粗類別、後期步回答細類別。
